# 训练出题多样性与高级产品思维设计

## 1. 背景

当前日常训练将五个维度分别绑定到一个固定框架：战略思维等于机会成本、系统设计等于模块解耦、数据决策等于因果验证、用户洞察等于 JTBD、商业思维等于 LTV/CAC。这使模型虽然能更换行业和业务名词，但题目的核心矛盾、答题动作和参考答案高度同质化。

本设计在不引入难度模型、不新增依赖、不修改数据库 Schema 的前提下，将出题从“维度 + 固定框架 + 模型随机发挥”改为“能力矩阵 + 受控抽题 + 结构化生成 + 双层去重”。

## 2. 目标

1. 每道题都训练一项可识别的高级产品判断能力，而不是让用户套用已经公布的框架。
2. 同一维度内连续训练时，子能力、题型、场景和核心矛盾应有计划地轮换。
3. 不同维度的题目应需要不同的认知动作，通用套话不能获得高分。
4. 题面保持开放诊断，不展示方法论名称和资料来源。
5. 第一层提示默认展示，只提供观察角度；答题后提供完整参考答案。

## 3. 非目标

- 本轮不实现 L1-L5 难度模型或用户等级推断。
- 本轮不改造 AI 接口鉴权、限流和用户模型配置。
- 本轮不建设书籍 RAG、外部知识库或在线抓取系统。
- 书籍、行业案例、产品复盘和跨学科资料只用于离线研究和能力归纳，不在用户界面展示来源，不将题目绑定到某几本书。

## 4. 方案选择

### 4.1 不采用：仅增强 Prompt

只增加“不要重复”、更多行业和更高 temperature，只能改变表面文案，无法阻止模型反复产生相同认知任务。

### 4.2 采用：能力矩阵 + 受控抽题

程序先选定子能力、题型、场景家族和决策矛盾，模型只负责将这个题目规格写成自然、可作答的 B 端场景。

### 4.3 有限采用：失败后单次重生成

不常态生成多个候选题再调用第二个模型评选。本地验证发现结构重复、答案泄露或输出不完整时，最多携带失败原因重生成一次。

## 5. 高级产品能力矩阵

能力矩阵是产品自有的内部知识结构，而不是书籍目录。每个能力项包含：

- `id`：稳定的英文标识。
- `dimension`：所属的现有五维度。
- `advancedBehavior`：高级产品经理在该场景中能做出的关键判断。
- `executionTrap`：执行层常见的思维惯性。
- `archetypes`：可以训练该能力的题型。
- `evaluationFocus`：评卷时必须观察的特定证据。

### 5.1 战略思维

1. 问题定义与机会范围。
2. 产品定位与战略一致性。
3. 组合取舍与路线图节奏。
4. 竞争变化下的差异化选择。
5. 短期业务结果与长期能力建设。
6. 停止、拒绝、自建、采购或合作的边界判断。

### 5.2 系统设计能力

1. 多角色与跨组织工作流。
2. 权限、治理、合规与效率的平衡。
3. 业务域边界与平台抽象。
4. 状态一致性、异常恢复与人工介入。
5. 批量操作、并发、版本与审计链路。
6. 历史系统迁移与渐进式演进。

### 5.3 数据决策能力

1. 目标、指标树与领先/滞后指标。
2. 异常定位、归因与混杂因素。
3. 实验、准实验与可证伪假设。
4. 不完全信息下的决策阈值。
5. 数据口径、样本偏差与测量误差。
6. 从分析结论到产品动作的闭环。

### 5.4 用户洞察与需求管理

1. 多源研究证据的合并与冲突解释。
2. 表面需求、任务、动机与约束的区分。
3. 多角色价值冲突与真实决策者识别。
4. 人群分层与不可平均的需求。
5. MVP 范围、验证顺序与退出条件。
6. 声音强度、需求价值与证据质量的分离。

### 5.5 商业思维

1. 用户价值、付费意愿与价值捕获。
2. 定价、包装与客户分层。
3. 单位经济、边际成本与规模效应。
4. GTM、采购链路、销售阻力与产品配合。
5. 留存、扩张、续费和客户成功机制。
6. 客户 ROI、企业回报与长期可持续性。

## 6. 题型和场景轴

### 6.1 题型

- `decision_memo`：在多个可行选项中做决策并说明改变决策的条件。
- `ambiguous_diagnosis`：面对异常或冲突信号，排列解释并设计调查路径。
- `discovery_plan`：定义未知问题、验证顺序和停止条件。
- `system_boundary`：设计角色、状态、边界、异常和演进路径。
- `metric_review`：定义或评审指标体系，处理口径与激励扭曲。
- `counterfactual_review`：复盘已发生的决策，区分运气、判断质量和可迁移经验。
- `stakeholder_challenge`：处理多角色冲突、激励不一致和组织约束。
- `executive_proposal`：向决策者提出方案，回应反对意见并设定承诺边界。

### 6.2 场景轴

- 业务领域：CRM、协同办公、采购、供应链、制造、财务、人力、客服、数据产品、开发者平台等。
- 产品阶段：新场景验证、成长期、企业客户扩张、平台化、成熟期效率优化。
- 核心矛盾：标准化与定制、短期收入与长期能力、合规与效率、局部最优与系统最优、转化与留存、大客户与主流客群等。
- 证据状态：信息不足、信号冲突、数据有偏、时间窗口受限或外部条件正在变化。

受控抽题不要求所有轴完全笛卡尔积。每个子能力只声明适用的题型和冲突，避免产生不自然的组合。

## 7. 抽题和去重

### 7.1 题目签名

每道新题都带有不直接展示给用户的 `questionMeta`：

```ts
interface TrainingQuestionMeta {
  dimension: string;
  subSkillId: string;
  archetypeId: string;
  contextFamily: string;
  productStage: string;
  tensionId: string;
  answerFormat: string;
  signature: string;
}
```

`signature` 由上述结构化标签组成，用于判断“认知任务是否重复”，不依赖题面文字是否相同。

### 7.2 选择算法

1. 根据当前维度取出可选子能力和题型。
2. 读取近期训练记录中的 `questionMeta`。
3. 排除最近 5 道题中出现过的完整签名。
4. 对重复的子能力、题型、场景和冲突分别扣分。
5. 优先选择近期出现次数最少的合法组合，并在同分候选中随机选择。
6. 前端在“换一题”时把本轮已生成但未作答的签名一并传入，避免换题时反复同一结构。

### 7.3 文本相似度

结构签名解决“题意相似”，字符级判断补充解决“题面改写”：

- 去除空白、标点和常见模板词。
- 计算中文字符 trigram Jaccard 相似度。
- 超过阈值时视为软失败，触发一次重生成。
- 阈值由现有题目样本测试校准，不依赖向量库或新库。

## 8. 生成协议

### 8.1 服务端输入

模型不再只收到“维度 + 框架”，而是收到：

- 子能力的高级行为和执行层陷阱。
- 选定的题型、场景家族、产品阶段和决策矛盾。
- 近期需要避免的题目摘要和结构签名。
- 当前用户的相关盲区，但只在与本题子能力匹配时使用。

### 8.2 模型输出

服务端使用结构化 JSON，而不再从两段自由文本中提取推荐理由：

```ts
interface GeneratedTrainingQuestion {
  title: string;
  scenario: string;
  task: string;
  defaultHint: string;
  secondaryHint: string;
  evaluationCriteria: Array<{
    id: string;
    label: string;
    description: string;
    weight: number;
  }>;
  questionMeta: TrainingQuestionMeta;
}
```

对客户端只返回题面、提示和不涉及内部研究来源的元数据。评分标准与题目绑定，在提交答案时传给评卷逻辑。

### 8.3 出题约束

- 题面不出现方法论、书名或作者名称。
- 不直接告诉用户应使用的分析步骤。
- 必须存在至少两个可辩护的解释或选项，避免唯一明显答案。
- 必须包含一个只有执行功能思维无法解决的业务矛盾。
- 不使用真实品牌搭配无来源的内部经营数据。
- 需要数字时明确其为“题设已知条件”，不声称是真实公司数据。

## 9. 提示设计

### 9.1 默认提示

第一层提示默认展示，长度为一句话。它只指出需要注意的信息类型或容易忽略的矛盾，不公布框架，不给出步骤。

示例：

- “先判断这些数字是结果，还是足以解释结果的证据。”
- “注意提需求的人、真正使用的人和最终承担成本的人可能不是同一个角色。”

### 9.2 进一步提示

保留一个由用户主动展开的第二层提示。它可以补充一个需要比较的角度或需要验证的未知量，但仍不提供答案结构。

默认提示是训练设计的一部分，不降分。第二层提示的使用可记入 `ai_feedback` 供未来分析，本轮不建立新的分数惩罚规则。

## 10. 评卷与参考答案

### 10.1 题目特定的评卷标准

保留综合分数和现有反馈展示能力，但不再仅使用“理解、框架、方案、决策逻辑”四个通用项。评卷模型同时收到本题的 `evaluationCriteria`，并为每个特定标准给出证据、差距和改进方向。

通用套话如“先明确目标、再看数据、小范围验证”，如果没有完成本题特定的认知动作，不得得到高分。

### 10.2 参考答案

答题后展示完整参考答案。参考答案要求：

- 在评价用户答案前先独立求解，避免只是将用户答案润色。
- 给出一个可辩护的结论或行动，并明确其假设、证据、取舍和改变结论的条件。
- 说明至少一种其他合理选择在什么条件下更优，避免将产品判断伪装成唯一标准答案。
- 不展示方法论来源，不引用书籍。
- 形式跟随 `answerFormat`，可以是决策备忘录、调查计划、指标评审、系统边界设计、商业测算或复盘结论，不统一套用同一篇章结构。

## 11. 数据流与持久化

1. 前端请求出题时提交当前维度和本轮需要排除的题目签名。
2. `/api/train` 读取近期 `training_records.ai_feedback.question_meta`，选择训练目标后生成结构化题目。
3. 前端展示题面和默认提示，并保存 `questionMeta`、`evaluationCriteria` 和第二层提示。
4. 用户提交后，评卷请求携带该题的结构化信息。
5. 评卷结果生成题目特定反馈和参考答案。
6. `/api/training/record` 继续写入现有 `training_records`，并将 `question_meta`、特定评价结果和提示使用情况放入 `ai_feedback` JSONB。
7. 不新增表或列，历史记录没有 `question_meta` 时按旧数据兼容。

## 12. 组件边界

### 12.1 `src/lib/training/capability-catalog.ts`

维护能力矩阵、题型、适用场景和评价重点。文件中使用英文 ID，中文说明服务 Prompt 与产品运营。

### 12.2 `src/lib/training/question-generation.ts`

负责目标选择、签名生成、近期覆盖统计、字符相似度、AI JSON 归一化和题目质量验证。该模块不依赖 React 或 Supabase，便于单元测试。

### 12.3 `src/app/api/train/route.ts`

只负责请求校验、读取个性化上下文、调用目标选择器、组装 Prompt、调用模型、执行有限重试和返回结果。

### 12.4 `src/components/training/TrainingSessionClient.tsx`

扩展题目状态，展示默认提示和可展开的第二提示，换题时传入本轮排除签名，提交时携带题目评价信息。

### 12.5 `src/lib/training/personalization.ts`

保留评价归一化与旧数据兼容，扩展评价类型以容纳题目特定标准、参考答案、可辩护的替代路径和 `question_meta`。

## 13. 错误处理

- AI 输出无法解析或缺少硬性字段：携带验证错误重生成一次；再失败则返回可重试错误，不展示半截题目。
- 只有文本相似度超阈值：视为软失败，重生成后在两个可解析结果中选相似度更低的一个。
- 近期记录或个性化查询失败：使用当前维度的能力矩阵继续出题，但记录服务端错误，不静默伪装为完整个性化。
- 旧评卷结果缺少新字段：继续使用现有归一化默认值，历史页不报错。

## 14. 验证与验收

### 14.1 单元测试

- 每个维度都有完整且 ID 唯一的子能力定义。
- 相同维度连续选择时，最近 5 道不重复完整签名。
- 子能力、题型和场景的近期覆盖会影响选择排序。
- 本轮未作答的排除签名生效。
- 字符 trigram 相似度可识别题面近义改写。
- AI 结构归一化能处理代码块、缺失可选字段和非法权重。
- 题目验证会拒绝方法论泄露、直接给步骤和缺少决策矛盾的题目。
- 旧评价 JSON 仍能正常渲染。

### 14.2 批量质量审计

提供一个非 CI 的本地审计脚本，在有 API Key 的环境生成每个维度至少 5 道题，输出：

- 子能力、题型、场景和冲突覆盖率。
- 完整签名重复率。
- 题面字符相似度最高的题对。
- 方法论名称或答题步骤泄露情况。
- 行业和产品类型的过度集中情况。

### 14.3 产品验收标准

1. 每个维度连续生成 5 道题，不重复子能力 + 题型组合。
2. 全部题面不显示方法论或资料来源。
3. 每道题都有默认提示，提示不直接给出分析步骤。
4. 答题后都有完整参考答案，且参考答案格式与本题题型匹配。
5. 用同一段通用套话回答五个维度的题目，特定评价项不得评为良好或优秀。
6. 相同用户连续换题时，新题不使用本轮已排除的结构签名。
7. TypeScript、ESLint、Next.js build 和 `./init.sh` 全部通过。

## 15. 风险与缓解

- **能力矩阵过度理论化**：每个子能力必须同时定义可观察行为、执行层陷阱和可出题场景，不只保留抽象名词。
- **组合数量多但不自然**：子能力只绑定合法题型和冲突，不做无约束随机组合。
- **过度去重导致出题失败**：区分硬失败和软相似，软相似在重试后选择较优候选，不无限循环。
- **参考答案被误解为标准答案**：同时说明其假设和可辩护的替代路径。
- **历史数据没有元数据**：选题器允许元数据为空，新记录逐步建立覆盖状态，不做迁移。

预计涉及：

- 改造 `/api/train` 的生成和评卷协议。
- 扩展训练页题目状态、默认提示、第二层提示和参考答案展示。
- 扩展 `ai_feedback` 内的兼容字段，不改 Schema。
